# Skill backorder-api — API Backorder.ru

Навык для агента, который работает с публичным API Backorder.ru: переводит
задачу пользователя в фильтры GET-запроса, выполняет поиск, подсчёт и
постраничное получение доменов, делает выгрузки JSON/CSV и корректно
обрабатывает лимиты и ошибки сервиса.

Карта параметров проверена 30.10.2026 по текущему интерфейсу Chrome и
спецификации OpenAPI. Сайт и API новее старой страницы документации, которую
чаще всего находят в поиске, поэтому устаревшие примеры вида
`disp=1&expired=1&by=...` не используются.

## Возможности

- **Три интерфейса под задачу.** Основной API `backorder_list` с записями и
  агрегациями, файлы выгрузки `/json/` и `/csv/` (другая схема, до 30 000
  строк, без пагинации) и точечный `backorder_list.mget` для конкретного
  списка доменов.
- **Карта фильтров сайта → GET-параметры.** Актуальные имена полей: ИКС →
  `x_value`, тИЦ → `yandex_tic`, доноры → `donors`, трафик → `visitors`,
  вид регистрации → `old_type`; сортировка этих же колонок использует другие
  имена. Списки в API передаются через запятую, в hash страницы — через `|`.
- **Перенос ссылок из браузера.** Утилита читает hash страницы
  (`#filter_params=...&zones=ru|...`), превращает его в серверный query,
  переворачивает направление возрастной сортировки и отбрасывает
  непереносимое состояние интерфейса.
- **Особые случаи задокументированы.** Корзина и флажки «Заказанные» /
  «В корзине» обрабатываются клиентом и не воспроизводятся на сервере;
  `old_type` одновременно управляет возрастом и датой регистрации;
  `include=org,person` — ИЛИ между типами владельца, а не общий оператор
  для всех значений.
- **Выгрузка с контролем полноты.** Размер выборки оценивается через
  агрегацию основного API; при превышении лимита экспорта выборка
  разбивается по непересекающимся условиям или листается через `offset`.
- **Уважение к лимитам сервиса.** Интервал между запросами не меньше 1,2
  секунды, при 429 учитывается `Retry-After` (не более двух повторов), при
  `access_blocked` и CAPTCHA запросы прекращаются, защита не обходится.
- **Валидация ответов.** HTML и CAPTCHA вместо данных, объект `error`,
  неожиданная схема и посторонние редиректы распознаются как ошибка; `null`,
  отсутствующие поля и дату-заглушку `1970-01-01` навык не подменяет нулём
  или реальной датой.

## Установка

Репозиторий: <https://github.com/z-serg/webmaster-agents-skills>

Скилл устанавливается в каталог навыков агента `~/.agents/skills/` — достаточно
скопировать туда папку `backorder-api` из репозитория.

### Быстрая установка (рекомендуется)

```bash
git clone https://github.com/z-serg/webmaster-agents-skills.git
bash webmaster-agents-skills/backorder-api/install.sh
```

Скрипт создаёт симлинк в `~/.agents/skills/`, поэтому скилл обновляется через
`git pull` без переустановки. Параметры: `--copy` — копирование вместо симлинка,
`--dest ПУТЬ` — другой каталог установки, `--force` — заменить существующую
установку (прежняя сохранится рядом с суффиксом `.bak.<дата-время>`),
`--help` — справка. Если цель уже установлена этим скриптом, повторный запуск
ничего не меняет.

### Ручная установка

Вариант 1 — клонирование и симлинк:

```bash
git clone https://github.com/z-serg/webmaster-agents-skills.git
mkdir -p ~/.agents/skills
ln -s "$(pwd)/webmaster-agents-skills/backorder-api" \
  ~/.agents/skills/backorder-api
```

Вариант 2 — копирование:

```bash
git clone https://github.com/z-serg/webmaster-agents-skills.git
mkdir -p ~/.agents/skills
cp -r webmaster-agents-skills/backorder-api ~/.agents/skills/
```

Для обновления повторите копирование.

Зависимостей нет: утилите нужен только Python 3.10 или новее со стандартной
библиотекой. После установки перезапустите агента, чтобы он подхватил новый
навык.

## Использование

Навык срабатывает автоматически по запросам об API backorder.ru, его фильтрах
и выгрузке доменов. Примеры запросов:

- «Выгрузи свободные домены .ru с ИКС от 100 в CSV»
- «Посчитай, сколько доменов удаляется завтра в зонах .ru и .рф»
- «Получи метрики доменов sib.ru и moonbot.ru»
- «Перенеси этот фильтр со страницы backorder.ru в API-запрос»

### Запуск утилиты вручную

```bash
python3 scripts/backorder_api.py url --target api \
  --params '{"filter_params":"expired","zones":["ru"],"x_value":100,"limit":10}'

python3 scripts/backorder_api.py fetch --target api \
  --params '{"filter_params":"deleted_next","include":["interesting"],"limit":10}' \
  --output /absolute/path/domains.json

python3 scripts/backorder_api.py url --target json \
  --from-url 'https://backorder.ru/#filter_params=expired&zones=ru%7Cxn--p1ai'

python3 scripts/backorder_api.py fetch --target mget \
  --params '{"domain":["sib.ru","moonbot.ru"]}' \
  --output /absolute/path/exact-domains.json
```

Действия: `url` — напечатать готовый URL, `fetch` — выполнить запрос и
сохранить ответ в `--output`. Цели: `api`, `json`, `csv`, `mget`. Источник
параметров: `--params` (серверные параметры JSON-объектом) или `--from-url`
(hash страницы, ссылка API или экспорта). Утилита выполняет один запрос без
автоматической пагинации и намеренно отклоняет устаревшие имена, параметры
авторизации и локальные фильтры корзины (`cart`, `in_cart`, `ordered`,
`my_orders`) вместо молчаливого изменения смысла. Результат `fetch` — JSON с
путью файла, числом строк и размером. Подробности — в
[references/filters.md](references/filters.md) и [references/api.md](references/api.md).

## Границы

- Только публичные методы чтения данных: заказы, списание средств, отмена
  заказов, смена NS и регистрация доменов находятся за пределами навыка.
- Авторизация не используется: `my_orders` и персональные методы не
  поддерживаются, секреты не запрашиваются и не сохраняются.
- Экспорт `/json/` и `/csv/` ограничен 30 000 записями и игнорирует пагинацию;
  полнота выборки оценивается отдельно и честно сообщается пользователю.
- Ограничения частоты не обходятся: при CAPTCHA и `access_blocked` запросы
  прекращаются с сообщением пользователю.
- Карта фильтров — снимок интерфейса на 30.10.2026; при изменении сервиса
  параметр сверяется по ссылке «JSON»/«CSV» и фактическому запросу в Network.
