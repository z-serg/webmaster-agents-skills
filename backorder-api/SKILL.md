# Backorder.ru API

Переводи задачу пользователя в фильтры и выполняй запросы к Backorder.ru. Карта параметров проверена в Chrome 30.10.2026. Сайт и OpenAPI новее страницы документации, которую часто находят в поиске.

## Источники и выбор интерфейса

- Актуальная спецификация: <https://backorder.ru/api/api.yaml>, просмотр: <https://backorder.ru/api>.
- Интерфейс фильтров: <https://backorder.ru/> → «Все фильтры».
- Старая инструкция: <https://doc.backorder.ru/servis-backorder-ru/ispolzovanie-api/vygruzka-dannyh>. Не конструируй новые запросы по её примерам `disp=1&expired=1&by=...`.
- Для словаря всех фильтров, особых случаев и сортировки читай [references/filters.md](references/filters.md).
- Для схем ответов, выгрузки и дополнительных методов читай [references/api.md](references/api.md).
- При проверке происхождения параметров используй [references/verification.md](references/verification.md). Сырые наблюдения и каталог регистраторов загружай только при необходимости.

Для поиска, подсчёта и постраничного получения используй `GET /billmgr?func=backorder_list&out=backorder&filter=off`. Ответ содержит `records` и обычно `aggregation`.

Для файла выгрузки используй `/json/?...` или `/csv/?...`. Эти методы возвращают другую схему, ограничены 30 000 записями и игнорируют пагинацию. Если нужна полная выборка, сначала оцени её размер через основной API; при превышении лимита разбей её по непересекающимся условиям или используй основной API с `offset`.

Для точного списка доменов используй `func=backorder_list.mget&domain=...&out=backorder`, а не поиск по шаблону.

## Работа с фильтрами

1. Уточни смысл выборки из запроса пользователя: основной режим, зоны, шаблон, метрики, даты, включения и исключения. Не добавляй критерии от себя.
2. По карте фильтров выбери актуальные имена. Например: ИКС → `x_value`, тИЦ → `yandex_tic`, доноры → `donors`, трафик → `visitors`; сортировка этих колонок использует другие имена.
3. Передавай списки `include`, `exclude`, `zones`, `registrars` одной строкой через запятую. В hash страницы они разделяются `|`. Кодируй значения через `urlencode`/`URLSearchParams`.
4. Из ссылки сайта бери часть после `#`; браузерный hash серверу не передаётся. Для сортировки `age`, `age_first_reg`, `age_prev_reg` переверни `asc`/`desc` при переносе из hash в API. Ссылка «JSON» уже содержит серверное направление.
5. Проверь сочетания: `filter_params` — одно значение; `old_type` одновременно управляет возрастом и датой регистрации; `include=org,person` означает ИЛИ между типами владельца. Не объявляй весь список `include` простым AND или OR.
6. Корзина локальна в браузере: `filter_params=cart` и `exclude=in_cart` не воспроизводят её содержимое на сервере. Получи конкретный список доменов из явно выбранной пользователем корзины, запроси `mget`, затем примени нужные условия локально. `exclude=ordered` также участвует в клиентской обработке; не обещай одинаковую выборку при прямом запросе.
7. Сначала выполни небольшой запрос (`limit=1–10`) и проверь HTTP-статус, отсутствие `error`, схему и смысл полученных строк. HTTP 200 с пустой выборкой — корректный результат; HTML, CAPTCHA и объект `error` — ошибка.

Пороговые метрики задают минимум, а не точное значение. Даты передавай в `YYYY-MM-DD`, не фиксируй дату «завтра»: `deleted_next` означает следующий день удаления, который может быть позже календарного завтра.

При изменении интерфейса сверяй параметр по ссылке «JSON»/«CSV» и фактическому `backorder_list` в Network. Смена hash сама по себе не всегда очищает старые поля состояния: для контрольного опыта используй «Отменить поиск» или новую вкладку. Если результатов нет, ссылки выгрузки могут отсутствовать.

## Утилита

`scripts/backorder_api.py` использует только стандартную библиотеку Python 3, строит URL и сохраняет один ответ. Автоматическую пагинацию не выполняет.

```bash
python3 scripts/backorder_api.py url --target api \
  --params '{"filter_params":"expired","zones":["ru"],"x_value":100,"exclude":["dash","rkn"],"limit":10}'

python3 scripts/backorder_api.py fetch --target api \
  --params '{"filter_params":"deleted_next","include":["interesting"],"limit":10}' \
  --output /absolute/output/domains.json

python3 scripts/backorder_api.py url --target json \
  --from-url 'https://backorder.ru/#filter_params=expired&zones=ru%7Cxn--p1ai'

python3 scripts/backorder_api.py fetch --target mget \
  --params '{"domain":["sib.ru","moonbot.ru"]}' \
  --output /absolute/output/exact-domains.json
```

Пути к скрипту в примерах относительны к папке скилла; в другой рабочей папке подставь абсолютный путь. Путь результата выбирай по задаче и правилам текущего рабочего пространства. `--params` всегда означает серверные параметры; `--from-url` различает hash и готовый API/экспортный query. Утилита намеренно отклоняет устаревшие имена, параметры авторизации и локальные фильтры корзины вместо молчаливого изменения смысла.

В цикле запросов соблюдай интервал не меньше 1,2 секунды: в проверенном клиенте сайта стоит 1100 мс. Это наблюдение, не гарантия лимитов сервиса. При обычном 429 учитывай `Retry-After` и сделай не более двух повторов с увеличением паузы. При `access_blocked`, CAPTCHA или повторяющейся ошибке прекрати запросы и сообщи ограничение; не обходи защиту.

## Результат пользователю

Покажи критерии выборки, источник и время получения, количество строк, ссылку или сохранённый файл и фактические ограничения полноты. Для ответа через основной API учитывай `null`, отсутствующие поля и даты-заглушки `1970-01-01`; не подменяй их нулём или реальной датой. Названия колонок экспортного и основного API нормализуй только явно.

Методы заказов, списания средств, отмены заказов, смены NS и регистрации доменов находятся за пределами этого скилла по выгрузке данных. Наличие GET-метода в общей спецификации не делает такую операцию чтением.
