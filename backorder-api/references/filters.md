# Карта фильтров Backorder.ru

Проверено 30.10.2026 по текущему Chrome-интерфейсу и OpenAPI. «UI» ниже означает наблюдавшуюся сериализацию; это не обещание одинаковой серверной семантики для клиентских фильтров.

## Строковые и числовые поля

| Поле сайта | GET-параметр | Значение и замечания |
|---|---|---|
| Верхняя строка поиска | `contains` либо метод `backorder_list.mget` | Обычный поиск передаёт `contains`; точный поиск и список доменов могут переключать клиент на `mget`, где используется `domain` |
| Содержит | `contains` | Строка шаблона, например `^mos?ow*.ru$` |
| Поиск по org | `org` | Строка правил, например `!^tevron\|netbox*$` |
| ИКС ≥ | `x_value` | Неотрицательное целое |
| тИЦ ≥ | `yandex_tic` | Неотрицательное целое |
| Доноры ≥ | `donors` | Неотрицательное целое |
| Трафик ≥ | `visitors` | Неотрицательное целое; не `traffic`, которое используется в сортировке |
| Возраст ≥ | `old` | Число лет; вид регистрации задаётся `old_type` |
| Длина от | `length_ge` | Нижняя граница, OpenAPI: 2–63, длина IDNA-декодированного имени |
| Длина до | `length_le` | Верхняя граница, OpenAPI: 2–63 |

В шаблонах: `^` — начало, `$` — конец, `?` — один символ, `*` — произвольная последовательность, `!` — отрицание в начале правила. Это специальный синтаксис сервиса; не передавай произвольные регулярные выражения PCRE как заведомо поддерживаемые.

В OpenAPI для `contains` указаны разделители правил: запятая, пробел и `|`; для `org` интерфейс явно показывает `|` и запятую. При этом текущий frontend при наличии `|` в `contains` может перейти к **точному списку через mget**. Поэтому набор шаблонов в прямом API и похожая строка в UI могут давать разные результаты. Для нескольких точных доменов выбирай `mget`; шаблоны проверяй через `backorder_list`.

В таблице `\|` — экранирование Markdown, в передаваемом значении нужен обычный символ `|`.

## Даты и регистрация

| Поле/переключатель | GET-параметр | Формат |
|---|---|---|
| Дата освобождения с | `freedate_start` | `YYYY-MM-DD` |
| Дата освобождения по | `freedate_end` | `YYYY-MM-DD` |
| Без расчета / C расчетом | `real_free_date` | Наблюдалось: «Без расчета» → `off`, «C расчетом» → `on` |
| Дата регистрации с | `create_date_ge` | `YYYY-MM-DD`, включительная нижняя граница |
| Дата регистрации по | `create_date_le` | `YYYY-MM-DD`, включительная верхняя граница |
| Текущая | `old_type` отсутствует | В OpenAPI также разрешено `current_creation` |
| Первичная | `old_type=first_creation` | Самая первая регистрация |
| Прошлая | `old_type=previous_creation` | Предыдущая регистрация |

Переключатель проходит цикл: текущая → первичная → прошлая → текущая. На текущей UI убирает параметр. Выбор действует **одновременно** на `old` и оба `create_date_*`.

По описанию OpenAPI `real_free_date=on` использует поле `free_date` из WHOIS, а `off` — `delete_date`, учитывающее дневной лимит удаления. Подписи UI приведены буквально: не выводи обратную семантику из слов «с расчётом». Для бизнес-критичного выбора даты сравни поля ответа. На сортировку `order_by=date` этот параметр тоже влияет.

Проверено последовательное добавление всех четырёх границ и обоих режимов. Произвольные значения дат и все интервалы не перебирались.

## Зоны и регистраторы

| Поле | GET | Hash страницы |
|---|---|---|
| .ru | `zones=ru` | `zones=ru` |
| .рф | `zones=xn--p1ai` | `zones=xn--p1ai` |
| Обе зоны | `zones=ru,xn--p1ai` | `zones=ru\|xn--p1ai` |
| Регистратор | `registrars=REGRU-RU` | Такое же значение |
| Несколько регистраторов | `registrars=REGRU-RU,RU-CENTER-RU` | Значения через `|` |

Не добавляй точку перед зоной. OpenAPI допускает также `рф`; текущий UI выводит punycode. Нет выбранных зон/регистраторов — отсутствие соответствующего ограничения; пустые массивы могут сериализоваться как пустая строка.

Группа **REGRU** — раскрывающийся элемент UI, а не код регистратора. В ней были `REGRU-REG-RIPN`, `REGRU-RF`, `REGRU-RU`. Параметр должен содержать точные дочерние коды. В текущем интерфейсе 140 раскрывающихся групп и 369 дочерних/одиночных кодов; все 369 отдельно включены и выключены с проверкой ссылки выгрузки. Снимок кодов: [registrars.json](registrars.json). Список динамический: актуальные группы и счётчики получай из `aggregation.registrars` основного API, не считай снимок закрытым enum.

«Выбрать всех» передаёт все доступные коды через запятую; «Сбросить» очищает `registrars`. Обычно для отсутствия ограничения лучше опустить параметр: это не фиксирует устаревающий список.

## Основной режим: один `filter_params`

| Подпись | Значение |
|---|---|
| Сегодня / Удаляются сегодня | `deleted_today` |
| Завтра / Удаляются DD.MM | `deleted_next` |
| Истекшие / Истекший срок | `expired` |
| Освободились сегодня | `freed_today` |
| Свободные | `is_free` |
| Все / Все домены | `all_domains` |
| Судебные | `judicial` |
| Домены в стоп-листе | `stop_list` |
| Корзина / Отображать только → В корзине | `cart` **(клиентский режим)** |

Значение по умолчанию сайта: `expired`. Последующий выбор заменяет предыдущий, а не добавляет ещё один режим. `deleted_next` зависит от расписания удаления: при проверке это было 03.11.2026, а не 31.10.2026. Когда `aggregation.filter_params.deleting_today=0`, пункт «Сегодня» может скрываться; в отдельной вкладке с hash `filter_params=deleted_today` он был выбран, сервер вернул ноль на контрольной выборке.

`aggregation.filter_params` использует **другие имена ключей**: `deleting_today`, `deleting_next`, `is_judicial`, `is_blocked`. Не подставляй их автоматически вместо значений запроса из таблицы.

## Исключить: список `exclude`

| Флажок | Токен |
|---|---|
| С тире | `dash` |
| С истекшим сроком | `expired` |
| Свободные | `free` |
| Интересные | `interesting` |
| С буквами | `letters` |
| Заказанные | `ordered` **(клиентская обработка; отсутствует в enum OpenAPI)** |
| Судебные | `judicial` |
| pendingDelete | `pendingdelete` |
| С цифрами | `digits` |
| В корзине | `in_cart` **(локальная корзина; отсутствует в enum OpenAPI)** |
| Стоп-лист | `blocked` |
| В реестре РКН | `rkn` |
| С трафиком | `traffic` |
| С буквами и цифрами | `letterdigit` |

Пример: `exclude=dash,digits,rkn`. Исключения накапливаются, снятие флажка удаляет токен. `letterdigit` — отдельное условие, не сокращение для `letters,digits`: исключение смешанных имён отличается от исключения всех имён, содержащих буквы или цифры.

Для локальных списков/mget клиент проверяет `ordered` по `is_intercepted`, а `in_cart` — по локальному списку `bo.cart`. У обычного поиска frontend также делает клиентскую обработку этих двух условий; серверный `exclude=in_cart` без конкретного списка не имеет доступа к корзине браузера. На контрольной выборке из двух доменов прямой API с `filter_params=cart` вернул оба домена, хотя корзина была пуста. Поэтому наличие токена в ссылке экспорта **не доказывает** переносимость его смысла.

## Отображать только: `include` и особая корзина

| Флажок | Параметр |
|---|---|
| Интересные / ⭐ Интересное | `include=interesting` |
| Юр. лиц | `include=org` |
| Физ. лиц | `include=person` |
| pendingDelete | `include=pendingdelete` |
| В реестре РКН | `include=rkn` |
| В корзине | **`filter_params=cart`**, не `include=cart` |
| Мои заказы (при авторизации) | `include=my_orders`; есть в OpenAPI, в неавторизованном UI не проверялся |

Списки передавай через запятую, например `include=interesting,org`.

Наблюдавшаяся серверная логика на контрольной паре `sib.ru` (юрлицо) / `moonbot.ru` (физлицо): `org` → один, `person` → один, `org,person` → оба. Это ИЛИ между двумя типами владельца. `interesting,rkn` и `org,person,rkn` дали ноль, поскольку эти домены не в РКН. Не обобщай все значения `include` до одного логического оператора; для локального mget текущий frontend вообще проверяет включения через `every`, что может отличаться от основного API.

Противоположные флажки не всегда взаимно снимаются. UI разрешил `include=interesting&exclude=interesting`, а сервер вернул ноль. Не исправляй противоречивый запрос молча. Корзина — исключение: её флажок заменяет основной режим и при выключении восстанавливает предыдущий.

## Сортировка, пагинация и служебные поля

| Колонка | `order_by` |
|---|---|
| Домен | `domain` |
| ⭐ | `hotness` |
| Стоимость | `price_next` |
| ИКС | `x_value` |
| тИЦ | `tic` |
| Доноры | `donors` |
| Трафик | `traffic` |
| Регистратор | `registrar` |
| Возраст: текущая регистрация | `age` |
| Возраст: первичная регистрация | `age_first_reg` |
| Возраст: прошлая регистрация | `age_prev_reg` |
| Дата освоб. | `date` |

Для API `sort_order=asc|desc`. UI при первом выборе новой колонки ставит `desc` в hash, повторный клик меняет направление. **Для трёх сортировок возраста** экспорт и сетевой API меняют направление на противоположное относительно hash: hash `order_by=age&sort_order=desc` → API `order_by=age&sort_order=asc`. Это преобразование не нужно повторять для готовой ссылки `/json/`, `/csv/` или `/billmgr`.

Меню возраста **в таблице** выбирает отображаемую регистрацию и сортировку; переключатель `old_type` **в фильтре** определяет условия возраста/даты. Не смешивай эти две настройки.

| Параметр | Назначение |
|---|---|
| `limit` | Размер страницы основного API: OpenAPI 0–30000; UI предлагает 50/100/250/500 |
| `offset` | Смещение с нуля; UI при следующей странице с `limit=50` передал `offset=50` |
| `content_only=off` | Получить агрегации вместе с записями |
| `content_only=on` | Только записи, агрегации могут отсутствовать; UI использует при пагинации |
| `exact_first=on|off` | Документированный приоритет точных совпадений; отдельного флажка в проверенной панели нет |
| `ext=1` | Состояние развёрнутой панели, встречается в hash/экспорте; не является критерием отбора, можно удалить из API |
| `func=backorder_list` | Метод при обращении через `/billmgr` |
| `out=backorder` | JSON-ответ основного API |
| `filter=off` | Обязательное по OpenAPI отключение собственного фильтра BILLmanager |

При смене условий/размера страницы UI сбрасывает `offset=0`. В `/json/` и `/csv/` `limit`, `offset`, а также старые `page`, `items` не дают постраничную выгрузку. Это проверено: запрос экспорта с `limit=1` по выборке из двух доменов вернул обе строки.
