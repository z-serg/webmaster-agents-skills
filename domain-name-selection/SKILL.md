# Подбор доменного имени

Доведи подбор до проверенных рекомендаций. Различай три независимых свойства:
качество имени, текущую занятость и историю использования. Не называй домен
«не дропом» только потому, что архив или поисковик не нашли записей.

## Бриф и границы

Возьми из задачи тематику, назначение сайта, аудиторию, язык, географию,
предпочтительные зоны и ограничения бренда. Если тема неизвестна, уточни её
перед генерацией. Остальные пробелы закрой разумными допущениями и назови их.
Для российского русскоязычного проекта при отсутствии предпочтений начни с
`.ru`; дополнительные зоны предложи по смыслу проекта. Не подменяй исходную
тему сайта темой примера из скрипта.

Если пользователь просит проверить готовый список или один домен, проверь его
без обязательной генерации ещё 50 имён. При полноценном подборе действуют все
этапы ниже. Регистрация, покупка, платные проверки и обращение к владельцам
не входят в подбор без отдельного запроса пользователя.

## 1. Сгенерируй и отфильтруй названия

Подготовь **не менее 50 подходящих уникальных основ имени** после первичного
отсева. Одно имя в разных зонах не увеличивает число основ. Сочетай несколько
направлений: действие или польза, тематическая ассоциация, метафора, короткое
брендовое имя. Не заполняй список случайными суффиксами и перестановками.

Для каждого имени сохрани предполагаемое чтение, смысл и полный домен.
Проверь соответствие теме, благозвучность, запоминаемость и возможность
продиктовать адрес без объяснения написания. Короткое имя предпочтительно,
но понятность важнее формального лимита длины. По умолчанию избегай цифр,
дефисов, двойных согласных, неоднозначных стыков, случайных аббревиатур,
нежелательных смыслов и очевидного сходства с известными брендами.

### Правило для русскоязычного сайта

- Используй латиницу, которая легко читается как русское слово или понятное
  сочетание русских слов. Английское слово не становится подходящим только
  благодаря латинскому написанию.
- В предполагаемом русском чтении **исключи ж, щ, ч, ш, й, х, ц**. Не обходи
  правило заменами `zh`, `shch`, `ch`, `sh`, `j/y`, `kh/h/x`, `ts/c`: проверяй
  звучание и исходное слово. Например, «сжимать» и «лёгкий» не подходят.
- Не запрещай букву `y` механически: она может передавать «ы»; всё равно
  оцени, однозначно ли читается целое слово. Предпочитай слова, для которых
  не нужно выбирать между несколькими очевидными транслитерациями.
- Проверяй русское чтение отдельно от синтаксической проверки скриптом.
  Эти ограничения относятся к основе имени, а не к обязательной зоне.
- Кириллические домены и `xn--` не предлагай по умолчанию. Явные изменения
  требований пользователя имеют приоритет над этими настройками.

Сохрани список с объяснениями в рабочей папке проекта и отдельный
`domains.txt`: по одному полному домену на строку. Не складывай результаты
подбора внутрь папки установленного навыка.

## 2. Проверь занятость

Используй [scripts/domain_check.py](scripts/domain_check.py), сначала прочитав
раздел запуска в [references/checks.md](references/checks.md). Скрипт работает
на стандартной библиотеке Python 3, сохраняет ответы, время и источник,
поддерживает продолжение и повторную проверку. В основе — WHOIS; при сбоях
предусмотрены WHOIS.vu для `.ru`/`.su` и RDAP реестра при наличии сервиса.
Исходный пример пользователя `/home/serg/Загрузки/domain_check.py` полезен как
ориентир; не запускай его без изучения: в нём зашиты чужие домены и путь вывода.

Проверь все полные домены. `taken` исключай из свободных, даже если регистрация
скоро заканчивается или домен продаётся. `available` означает явный ответ
WHOIS об отсутствии записи; `no_record` — соответствующий ответ RDAP. Оба
позволяют продолжить исследование, но наличие имени в продаже у регистратора
проверяется отдельно. Резервирование, ограничения зоны и премиальная цена
не устанавливаются по пустой записи реестра.

`unknown`, `error`, таймаут, CAPTCHA, HTTP 403/429/5xx и отсутствие DNS не
означают свободу. При противоречиях источников используй `unknown` до
повторной проверки реестра. Не выводи доступность из одной даты `created`.

## 3. Исследуй историю каждого предварительно свободного домена

Для **всех** `available` и `no_record`, а не только будущей тройки лидеров:

1. Запроси Wayback CDX скриптом. Используй `url=*.DOMAIN/`: эта документированная
   wildcard-форма включает поиск по домену, путям и поддоменам и эквивалентна
   `matchType=domain`. Если запрос с явным `matchType=domain` вернул 503,
   сначала попробуй эту форму без браузера. Запрос только корня
   недостаточен для полного охвата. Первые
   20 строк — выборка, не полная хронология. Не фильтруй сразу только HTTP 200:
   перенаправления и ошибки тоже содержат полезные следы.
   **При HTTP 503 обязательно повтори проверку через обычный интерфейс
   Wayback в браузере после попытки штатного wildcard-запроса**: открой
   календарь `https://web.archive.org/web/*/DOMAIN`
   или введи домен на главной странице. Аналогично поступай при других
   сбоях API. Не ограничивайся открытием CDX-ссылки в браузере: API может
   показывать «Temporarily Offline», когда календарь работает. Дождись
   результата для нужного домена; сама загрузка главной страницы его не даёт.
2. Если записи есть, открой несколько доступных снимков из разных периодов
   и определи, что там было: сайт по теме, другая организация, парковка,
   продажа, редирект, спам и т. п. Для сильных кандидатов с историей расширь
   выборку по периодам. Не называй минимум и максимум первых 20 строк датами
   первого и последнего существования сайта.
3. **Через браузер** открой Яндекс и Google с запросом `"domain-name.com"`:
   полное имя вместе с зоной в прямых двойных кавычках. Не заменяй его на
   `site:`, поиск без кавычек или один агрегированный веб-поиск. Дополнительные
   запросы допустимы после обязательного точного запроса в обоих поисковиках.
4. Для каждого поисковика запиши дату, URL запроса, результат и подтверждающие
   ссылки/снимок выдачи. Проверь реальные точные упоминания: похожее имя,
   поддомен чужого сайта, каталог автоматически сгенерированных доменов и
   предложение регистратора сами по себе не доказывают прошлый сайт.

Механика браузера, статусы и форма журнала — в
[references/checks.md](references/checks.md). При блокировке сохрани
`blocked`/`error`/`pending`; не превращай её в «ничего не найдено» и не
обходи CAPTCHA. Считай архив недоступным для партии только после проверки
обычного интерфейса в браузере. Если оба способа не работают, зафиксируй это,
продолжи доступные проверки и выдай честно предварительный результат.

## 4. Сделай вывод и ранжируй

Используй следующие выводы об истории, со ссылками на факты:

- **История использования подтверждена** — есть содержательные архивные
  страницы или убедительные датированные свидетельства. При свободном
  домене это признак прежнего использования и возможного дропа.
- **Есть следы, нужна проверка** — парковка, продажа, неоднозначные упоминания,
  недоступные снимки или противоречивые данные.
- **Следов не найдено в проверенных источниках** — CDX успешно пуст либо
  браузерная проверка архива успешно завершилась без снимков (укажи её охват),
  и оба поисковика проверены без релевантных следов. Это не доказательство
  отсутствия прошлых регистраций, санкций или скрытой истории.
- **Проверка неполная** — хотя бы один обязательный источник не проверен или
  недоступен; перечисли пробелы. Если история уже подтверждена другим
  источником, сохрани этот вывод и отдельно отметь неполноту покрытия.

«Подтверждённый дроп» пиши только при наличии свидетельства прекращения
прежней регистрации: исторического WHOIS/реестра, записи об освобождении
или сопоставимых данных. Дата первого снимка не является датой регистрации.
Не обещай чистую ссылочную историю, отсутствие фильтров или рост позиций.

Сначала применяй жёсткие условия брифа, свободу и риски истории; затем
сравни смысл, чтение, запоминаемость, отличимость и соответствие зоне.
Субъективную оценку не выдавай за измеренную SEO-метрику. Назови 5–10 лучших
или меньше, если только столько прошли проверки; не добивай количество
сомнительными именами. Если хороших свободных вариантов нет, подготовь ещё
одну осмысленную партию до 50 основ и повтори проверки. После двух партий
без результата покажи ограничения и предложи, что расширить; не уходи в
бесконечный перебор.

Для 3–5 финалистов по возможности проверь очевидные совпадения названия с
действующими проектами и доступность у регистратора; укажи обнаруженную
цену регистрации и продления только с актуальным источником, валютой и
датой. Это дополнительный скрининг, а не юридическое заключение. Если нет
данных о цене, так и напиши. Перед рекомендацией к регистрации обнови WHOIS
финалистов командой с `--refresh`; не используй старый кэш как текущее состояние.

## Результат

Начни с 1–3 рекомендаций и кратко объясни выбор. Дай таблицу лучших вариантов:
домен, чтение/смысл, занятость и время проверки, вывод об истории, результаты
Wayback/Яндекса/Google, оговорка или риск. Ссылайся на подтверждения.
Покажи воронку: сколько основ и полных доменов сгенерировано, сколько занято,
предварительно свободно, неопределённо, сколько получили все три проверки.
Отдельно отметь ограничения и изменения доступности после повторной проверки.

Полный список из 50+ основ, решения по отсеву, CSV/JSON и сырые ответы сохрани
в рабочей папке, а по запросу пользователя — в согласованный файл отчёта.
В чате не требуется печатать 50 строк, если полный список доступен по ссылке.
