# SEO-чек-лист технического аудита

Переработка полного чек-листа технического аудита из комплекта схемы
продвижения. Принцип этого референса: **всё, что агент может
проверить локальными скриптами, выполняется ими** — облачные сервисы
(Site Analyzer, Screaming Frog и т. п.) не нужны. Внешние панели
остаются только там, где данные существуют лишь у поисковика или
сервиса (индексация, фильтры, скорость по Lighthouse), а регистрация и
юридические действия — задачи человека.

Маркировка каждого пункта:

- **[скрипт]** — выполняется локально `scripts/site_audit.py`;
- **[панель]** — нужны данные из внешней панели (попроси у пользователя
  доступ, выгрузку или скриншот; сам не регистрируйся);
- **[человек]** — действие, которое нельзя автоматизировать (регистрация,
  уведомления, настройки у хостера);
- **[браузер]** — разовая проверка в браузере: инструменты агента
  (например, chrome-devtools-mcp) или вручную. Встретил CAPTCHA или
  блокировку — строгий стоп и честное сообщение пользователю; не
  обходи и не выдавай блокировку за «ничего не найдено».

## Как проводить аудит

```bash
# полный прогон: проверки сайта + обход страниц + сводка
python3 scripts/site_audit.py audit https://site.ru --out work/audit --max-pages 200

# только проверки уровня сайта (robots, sitemap, зеркала, SSL, 404, favicon)
python3 scripts/site_audit.py site https://site.ru --out work/audit

# точечная проверка списка URL (выгрузка, спорные страницы)
python3 scripts/site_audit.py urls --input work/urls.txt --out work/audit
```

Результаты: `site_report.md` (уровень сайта), `summary.md` и
`issues.csv` (проблемы по страницам с важностью), `pages.json` (полные
данные по каждой странице: мета-теги, топ слов, разметка, счётчики).
Скрипт уважает robots.txt; пороги в отчётах — эвристики, а не
официальные лимиты.

Короткий маршрут для новичка: разделы 1–2 по пометке «базово» + раздел
5 целиком — это покрывает минимум из версии чек-листа «Для новичков».

## 1. Системы аналитики и внешние сервисы

| Проверка | Критерий | Как выполняем |
|---|---|---|
| Счётчик Яндекс Метрики | установлен на всех страницах | **[скрипт]** crawl ищет код счётчика в HTML каждой страницы; регистрация счётчика — **[человек]** |
| Счётчик GA/GTM | аналогично | **[скрипт]** |
| Яндекс Вебмастер | сайт добавлен, права подтверждены | **[панель]** у пользователя |
| Google Search Console | сайт добавлен | **[панель]** |
| Bing Webmaster Tools | импорт из GSC; даёт старт в AI-поиске (Bing кормит нейроответы) | **[панель]** |
| Критические ошибки | разделы проблем в Вебмастере и GSC | **[панель]**: выгрузка «Проблемы сайта» / «Проблемы безопасности» |
| Индексация Яндекс и Google | число страниц в индексе, динамика | **[панель]**: Вебмастер → «Структура сайта»/«Проверка ответов», GSC → «Индексирование страниц»; сам факт индексируемости (noindex, robots, canonical) — **[скрипт]** |
| Яндекс Карты | карточка с адресом, фото, контактами, отзывы | **[человек]** |
| Google Business Profile | карточка заполнена, отзывы | **[человек]** |
| Региональность в Яндексе | регион продвижения указан в Вебмастере | **[панель]**: «Региональность» |

## 2. Техническая оптимизация и индексация

| Проверка | Критерий | Как выполняем |
|---|---|---|
| Возможность индексации | целевые страницы без noindex (meta и X-Robots-Tag), canonical не уводит на другой URL | **[скрипт]** `audit`; базово: главная и ключевые страницы |
| robots.txt | существует, не блокирует целевые страницы, указан Sitemap | **[скрипт]** `site`: наличие, запреты, сверка с sitemap (сколько URL из sitemap заблокировано) |
| sitemap.xml | найден (в robots или /sitemap.xml), валидный XML, актуальный lastmod, все URL доступны | **[скрипт]** `site` + `audit`: lastmod старше года, URL из sitemap, которых нет на сайте |
| Зеркала и технические дубли | www/без-www и HTTP/HTTPS склеены 301-редиректом в одну сторону | **[скрипт]** `site` |
| SSL-сертификат | HTTPS работает, редирект с HTTP, сертификат не истекает | **[скрипт]** `site` (проверка срока сертификата локально) |
| Битые ссылки (404) | внутренних битых нет, внешние проверены | **[скрипт]** `audit` (краулер собирает все внутренние ссылки и до 100 внешних) |
| Редиректы | нет лишних звеньев и циклов, рабочие цепочки короче | **[скрипт]** `audit` пишет цепочки полностью |
| Правильный 404 | несуществующая страница отдаёт 404, а не 200 (soft-404) | **[скрипт]** `site` |
| Favicon | есть /favicon.ico или link rel=icon | **[скрипт]** `site` |
| Мобильная адаптивность | meta viewport на всех страницах; официальная проверка Яндексом | viewport — **[скрипт]**; вердикт Яндекс Вебмастера — **[панель]** |
| Скорость | время ответа сервера, размер HTML; Core Web Vitals (LCP/INP/CLS) и Lighthouse | время/размер — **[скрипт]**; Core Web Vitals и Lighthouse — **[браузер]** через chrome-devtools-mcp (performance-трассировка + аудит категорий SEO/лучшие практики) по главной и 2–3 тяжёлым страницам; если он не подключён — предложи пользователю установить его, а при отказе `pagespeed.web.dev` вручную |
| Валидность HTML | код без критичных ошибок парсинга | грубая проверка — **[скрипт]** (ошибки HTMLParser); полный разбор — **[браузер]** `validator.w3.org/nu/` |
| Микроразметка | на всех типах страниц есть JSON-LD (Organization, Product, Article, BreadcrumbList…), JSON валиден | наличие, типы и валидность JSON — **[скрипт]**; семантическая валидация — **[панель]** валидатор Яндекса / validator.schema.org по 2–3 страницам каждого типа |
| Товарный фид | фид существует, отдаёт валидный XML/YML | доступность и валидность XML — **[скрипт]** (`urls` или fetch); кабинет Яндекс Маркета — **[панель]** |
| История домена | возраст от последней перерегистрации, следов санкций нет | WHOIS/RDAP — **[скрипт]** (`whois` или RDAP реестра), Wayback — **[браузер]** `web.archive.org` |
| Доступность сайта | сайт стабильно отвечает, нет микропадений | разовая проверка — **[скрипт]**; постоянный мониторинг — **[человек]** (бесплатный тариф аптайм-сервиса) |

## 3. Фильтры и санкции

| Проверка | Критерий | Как выполняем |
|---|---|---|
| Чёрные списки | сайт не помечен как опасный | **[браузер]** `yandex.ru/safety/` и Google Safe Browsing по домену |
| Хостовые фильтры | нет резких обвалов видимости | **[панель]** динамика видимости (Keys.so/SpyWords — выгрузка пользователя) |
| Вирусы и вредоносный код | посторонних инжектов в HTML нет | сигнатуры в HTML (обфусцированные скрипты, скрытые iframe) — **[скрипт]** просмотром pages.json; внешний антивирус-сканер — **[панель]** |

## 4. Юридические аспекты

| Проверка | Критерий | Как выполняем |
|---|---|---|
| 152-ФЗ: политика ПД и согласия | политика конфиденциальности со ссылкой на закон, согласие на обработку ПД, уведомление о cookies, строка согласия под формами | **[скрипт]** crawl ищет ссылки и типовые формулировки в подвале и у форм; подача уведомления в РКН — **[человек]** |
| Реквизиты продавца | ООО/ИП, ИНН, ОГРН, адрес в подвале | **[скрипт]** поиск реквизитов на главной/в подвале; дополнить данные — **[человек]** |
| Оферта и условия | публичная оферта (или «не является публичной офертой»), оплата, доставка, возврат, гарантии | **[скрипт]** наличие страниц и непустых текстов; тексты готовит **[человек]** |
| Маркировка рекламы | банеры и промо-ссылки промаркированы; информирование ≠ реклама | **[человек]** по юридической оценке |

## 5. Контент и мета-теги

| Проверка | Критерий | Как выполняем |
|---|---|---|
| Title | уникальный, информативный, 10–75 знаков, коммерческие приставки + топоним | дубли, пустые, длины — **[скрипт]** `audit`; качество формулировок — агент по сводке |
| Description | уникальный, УТП и коммерческие данные, до ~250 знаков | **[скрипт]** |
| H1 | ровно один, релевантный содержимому | **[скрипт]** (нет/несколько/дубли между страницами) |
| URL (ЧПУ) | транслит, короткие, без кириллицы и параметров, без .html/.php, вложенность до 4–5 уровней; ключ в URL | **[скрипт]** (все эвристики в отчёте); для новых страниц — правило из раздела «Советы» |
| Релевантность содержимому | самое частое слово страницы соответствует её теме и title | **[скрипт]**: топ слов каждой страницы в pages.json, расхождение с title — замечание в сводке |
| Объём текста | на целевых страницах достаточный текст (порог-эвристика 100 слов) | **[скрипт]** |
| Изображения | alt у большинства изображений | **[скрипт]** |
| Спамность текста | стилистические ошибки переспама | **[панель]** Тургенев (turgenev.ashmanov.com) по ключевым страницам |

## 6. Советы по типам сайтов

Важность: **1** — первоочередное, **2** — вторая очередь. Общие советы
применимы ко всем проектам; остальное сверяй с конкурентами из ТОПа
(этап 2 схемы) — у каждой ниши свои наборы элементов.

### Интернет-магазины

- **(1) Не удалять снятые с продажи товары.** Оставлять «не в
  наличии»; при удалении — 301-редирект на аналогичные страницы.
- **(1) SEO-фильтры без пустых выборок.** Не генерировать срезы, под
  которых нет товаров; бездумная генерация хоронит сайт. Срезы
  «категория + бренд» обычно безопасны. Конечные страницы фильтрации,
  оставленные под индекс, должны иметь содержание; пустые — закрыть.
- **(1) Микроразметка карточек и листингов** (schema.org: Product,
  Offer, BreadcrumbList) — наличие проверяет скрипт.
- **(1) Валюта у каждой цены.** Цена без валюты — ошибка.
- **(1) Товарная перелинковка** в карточке и категории — вхождение
  важных ключей.
- **(1) Названия товаров = частотная форма запроса** с указанием
  сущности: «ОП-245» — плохо, «Огнетушитель порошковый ОП-245» — хорошо.
- **(1) Число категорий**: проверить коммерческость единственного и
  множественного числа запроса категории.
- **(1) Топонимы в карточках товаров**: таб «Доставка» с выбором города
  или список крупных городов — все товарные запросы геонезависимые.
- **(1) Плоская структура URL**: без вложенности категорий в URL
  товаров (рекомендация, не правило).
- **(1) Гибридный фильтратор**: собрать фильтры конкурентов, вычистить
  дубли, внедрить; пустые срезы закрыть от индексации.
- **(2) Маски Title/Description** для массовых страниц (категория:
  «[Название] купить по цене от [мин. цена] — доставка по России»);
  лучше ручного нет ничего, но лучше маски, чем пусто.
- **(2) Корзина заметна с любой страницы** (привычное место — правый
  верхний угол).
- **(2) Древо категорий** с раскрытием полного списка подкатегорий.
- **(2) Отзывы на карточках** — плюс к ПФ и защита от «малоценных».
- **(2) Отзывы на Яндекс Картах** — мотивировать покупателей бонусами.

### Сайты услуг

- **(1) Блоки под интент запроса**: по запросу «…цены» на странице
  нужна таблица с ценами.
- **(1) Топоним в коммерческих добавках**: «…в Москве», купить/цена/
  заказать.
- **(1) Гибридная таблица цен**: собрать таблицы цен конкурентов по
  запросу, скомпоновать самую широкую, убрать дубли, внедрить.
- **(1) Анализ ТОП-10**: разобрать страницы конкурентов на элементы
  (текст, таблица, видео, отзывы, квиз) и внедрить повторяющееся.
- **(1) Отзывы на Яндекс Картах.**
- **(1) Калькуляторы и квизы** на страницах — сильные естественные ПФ.
- **(1) Привязка эксперта**: страница эксперта с биографией и
  сертификатами, статьи от его имени на сайте и внешних площадках.
- **(2) Оформленные контакты** (8-800, мессенджеры, e-mail в шапке).
- **(2) Портфолио и отзывы** отдельными проработанными страницами.
- **(2) Акции** — регулярно пополняемая страница.
- **(2) О компании и вакансии** (можно вакансии менеджеров/копирайтеров).
- **(2) Маски Title/Description** с топонимом и телефоном.

### Информационные сайты

- **(1) Оглавление статьи** якорными ссылками на разделы.
- **(1) Перелинковка**: в конце статьи — ссылки на связанные статьи и
  коммерческие разделы; по возможности ссылки на товары в тексте.
- **(1) Качество текста**: писать под интент, ключи — вокруг текста в
  активные элементы (например, оглавление).
- **(1) Заголовок и первый абзац**: заголовок-список на первом экране;
  первый абзац решает, останется ли читатель.
- **(1) Спамность** — проверять Тургеневым (**[панель]**).
- **(2) Блок автора** с ФИО, специализацией, ссылкой на страницу с
  биографией и материалами.
- **(2) Соцактивность**: лайки, комментарии, время чтения, кнопки
  «поделиться».

### Все типы сайтов

- **(1) Юридические страницы** — из раздела 4.
- **(1) Без иконок запрещённых соцсетей** (Instagram/Facebook) — риск
  штрафов.
- **(1) Маркировка рекламы** — разделять рекламу и информирование.
- **(1) Легальные изображения**: нейрогенерация или фотостоки; чужие
  картинки — судебный риск.
- **(1) Ключ в URL и в домене**: после YATI значимость выросла; покрытие
  домена «трёхбуквиями» запроса — один из значимых факторов.
- **(2) С главной — ссылки на все основные категории** (не только меню).
- **(2) Хостинг**: проверенный, желательно российский (риск удаления
  сайта/блокировки аккаунта у иностранных); домены — у российского
  регистратора.
- **(3) Длинные URL** — проверка скриптом (замечание «URL длиннее 120
  символов»).

## Порядок использования в этапе 3

1. Прогони `site_audit.py audit` — получишь уровень сайта и сводку по
   страницам.
2. Пройди разделы 1–5: закрой все **[скрипт]**-пункты из отчётов,
   собери список **[панель]**-пунктов и попроси у пользователя выгрузки,
   выполняемое человеком передай списком.
3. Сверь результат с типом сайта (раздел 6) — это вход в ТЗ на
   внедрение (этап 4).
